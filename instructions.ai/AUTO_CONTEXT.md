# Automatic Project Context

`scripts/bootstrap-project.sh` prepares any project folder for AI agents and IDEs.

## What It Does Automatically

The script scans the target project and creates or refreshes:

- `PROJECT_CONTEXT.md`
- `PROJECT_CONTEXT.generated.md`
- `ai-system/project_context.md`

It detects common technical context from files such as:

- `package.json`
- lockfiles
- `pyproject.toml`
- `requirements.txt`
- `README.md`
- `vercel.json`
- `netlify.toml`
- `render.yaml`
- `wrangler.toml`
- `Dockerfile`
- `prisma/schema.prisma`
- `drizzle.config.ts`
- `supabase/`
- `sql/`
- Tailwind and component config files
- Playwright, Jest, Vitest, and other dependency hints

## What It Cannot Know Automatically

Some context still needs a human or a project-aware agent:

- Actual business goal when README is missing or vague.
- Target users.
- Product priorities.
- Known bugs that are not documented.
- Private deployment rules.
- Design taste and brand direction.
- Roadmap decisions.

Agents must refine `PROJECT_CONTEXT.md` when they learn these details.

## Existing Customized Context

If `PROJECT_CONTEXT.md` already has custom content, bootstrap preserves it and
writes fresh detected data to `PROJECT_CONTEXT.generated.md`.

If `PROJECT_CONTEXT.md` is still the default template or was generated by
bootstrap before, bootstrap refreshes it automatically.

## Cross-IDE Behavior

Run bootstrap once per project folder. After that, opening the same folder in
Codex, Claude, Cursor, Antigravity, Windsurf, Trae, GitHub Copilot, JetBrains
agents, OpenCode, or another agent-aware IDE should expose the same local
instruction files.

You do not need to run bootstrap again for each IDE unless:

- You deleted the instruction files.
- You want to refresh auto-detected context after major stack changes.
- You copied only part of the project to a new folder.
